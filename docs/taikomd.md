# Minecraft 太鼓达人 Mod (VR/PC/实体街机) 架构设计文档

## 1. 项目概述
本项目旨在为 Minecraft（如“不夜城”服务器）开发一款高度还原街机体验的太鼓达人 Mod。支持 PC 键鼠/手柄、VR 体感挥棒、以及实体太鼓控制器外设。游戏强调多人联机、街机式大屏观战、投币游玩以及严格的音画同步。

## 2. 物理外设映射与核心判定逻辑
本设计深度参考了实机 HORI 太鼓控制器（PS2等）的物理结构。实机鼓面由**红线（中轴）**平分为左右两半（左咚/右咚），外圈为鼓边（左咔/右咔）。玩家在实机上的**蓝色波浪线轨迹**（左右手交替快速挥动扫击）与**边缘锯齿轨迹**（沿鼓边摩擦/连打），将在系统中被映射为高频的“滚奏扫描（Rolling Scan）”。VR 端摒弃复杂的动作手势识别，采用**纯空间几何碰撞检测**来复刻这种物理敲击感。

### 2.1 空间坐标系与基础设定
*   **鼓面中心点**：`(Cx, Cy, Cz)`，其中 Y 轴为垂直向上。
*   **鼓棒尖端坐标**：`P_tip = (X, Y, Z)`。
*   **有效击打高度（Hit Window）**：鼓面 `Y` 轴起，向上允许一定容差的高度区间。

### 2.2 判定区域划分（立体同心圆柱）
*   **咚（Don - 鼓面）**：内部实心圆柱，对应图片中红色圆圈内部。
    *   水平距离：`dist = √((X-Cx)² + (Z-Cz)²) <= R_don`（建议 R_don 约为 0.8）。
    *   高度限制：极薄，`Y` 在 `[Cy, Cy + 0.15]` 之间。
*   **咔（Ka - 鼓边）**：外部空心圆柱环（必须完全剔除咚的范围，防止边缘滚奏误判），对应图片中鼓外侧边缘。
    *   水平距离：`R_don < dist <= R_ka`（建议 R_ka 约为 1.3）。
    *   高度限制：稍厚，容错率更高，`Y` 在 `[Cy, Cy + 0.3]` 之间。

### 2.3 左右半区划分（对应图片红线中轴）
为匹配 TJA 谱面的四种音符（左咚、右咚、左咔、右咔），需进行 X 轴区域划分：
*   引入 `deltaX = X - Cx`（代表玩家击打点偏离中轴的程度）。
*   设置中轴死区（Deadzone），例如 `deltaX` 在 `[-0.05, 0.05]` 内不触发左右判定，防止正中心敲击产生歧义。
*   根据 `deltaX` 的正负，将击打结果映射为左/右对应的音符。

### 2.4 滚奏扫描模式（对应图片蓝色波浪线轨迹）
*   **线段采样（Sweep Test）**：针对玩家在鼓面上快速左右扫动导致的帧间跳跃，记录上一帧 `P_prev` 和当前帧 `P_curr`，对两点连线进行插值采样（如 5 个采样点），确保高频挥动不漏判。
*   **判定冷却锁（Cooldown）**：每次成功触发判定后，为该只手添加 40ms - 60ms 的冷却锁，防止一帧内触发多次判定。
*   **防误触方向检测**：要求鼓棒尖端具有向下的速度分量（`VelocityY < 0`）才允许触发判定，防止水平滑动（切西瓜）误触。

## 3. 网络同步与多人观战架构
采用**“逻辑判定与视觉渲染分离”**的原则，实现零延迟手感与正确的观战延迟补偿。

### 3.1 客户端本地预测（游玩者视角）
*   玩家击打时，**客户端立即**进行命中计算并播放打击特效和音效（零延迟手感）。
*   同时向服务器发送 `C2SPlayHitPacket`（包含：音符ID、命中时间戳、判定结果、击打位置）。

### 3.2 服务器权威校验与广播
*   服务器收到包后，校验时间戳是否在合理窗口内（防作弊）。
*   校验通过后，向所有客户端广播 `S2CPlayHitBroadcastPacket`（包含：玩家ID、音符ID、判定结果、**音符理论命中时间**）。

### 3.3 观战端延迟补偿（大屏幕）
*   **大屏幕渲染**：创建一个离屏渲染目标（Render Target），绑定到街机屏幕模型上，实时抓取游玩者的视角画面。
*   **特效回溯**：观战者收到 `S2CPlayHitBroadcastPacket` 时，音符可能已经在屏幕上飞过去了。此时，观战者客户端利用包内的“理论命中时间”，在音符的**历史正确位置**生成打击特效。观战者会看到：“玩家晚了一点点挥棒，但特效准确地亮在音符该在的位置，并显示‘良’”。

### 3.4 多人与观战音效规则
*   **双人游玩音效屏蔽**：在双人同屏游玩模式下，玩家A只会听到自己（本地）的敲鼓音效，**绝对听不到**隔壁玩家B的敲鼓音效，以防止节奏互相干扰。
*   **旁观者音效模式（默认：正解音）**：其他玩家在机台旁或看大屏幕时，默认听到的是**正解音（Autoplay）**。即敲鼓声音不跟着玩家实际的敲击动作走，而是自动在谱面正确的位置播放，保证观战听感完美。
*   **旁观者音效切换**：通过指令（推荐使用 `/taikomc screen setting`），管理员或玩家可以将旁观者的播放模式从“正解音”改为“实际敲击”。*（注：若改为实际敲击，网络延迟过大的玩家可能会导致听感上敲击音与歌曲节拍对不上，需自行承担体验下降的风险）。*

## 4. 音频与谱面系统 (TJA)
*   **谱面格式**：解析并支持标准 TJA 格式（支持单文件多难度 0-4）以及 osu! 的 `.osz` 格式（提取其中的音频和谱面）。
*   **音频同步**：需内置**延迟校准 GUI**。玩家需按节拍敲击，系统自动计算并应用全局延迟（Universal Offset）。
*   **数据导入**：模组本身**不附带**任何官方谱面和音频，完全交由玩家自行导入。

## 5. 版权合规与“空心化”策略
*   **法律风险规避**：万代南梦宫曾对包含官方资产的模拟器发起 DMCA 下架。模组必须采用“空心化”架构。
*   **禁用资产**：绝对不打包官方音频、图片、字体或官谱。
*   **视觉占位**：默认使用纯色几何体（圆柱/圆环）和无版权占位音效。对于 VR 端，可使用半透明线框 UI 提示判定区域。
*   **皮肤系统**：实现加载系统，允许玩家自行导入自定义图片（避免使用 osu! 官方素材，鼓励原创）。
*   **开源借鉴**：可参考 MIT 协议的 OpenTaiko 或 TJAPlayer3 的逻辑架构，但需用 Java 重写，不直接复制代码。

## 6. 游戏内设置项 (Settings)

### 6.1 音频与校准
*   **延迟调整**：点进去后进入一个迷你关卡，玩家跟着节奏敲完一遍后弹出GUI，让玩家确认是否应用推荐延迟或者自行调整。

### 6.2 仅限 PC 端设置
*   **动作展示**：游戏中敲打太鼓的时候旁边人眼中可以看见玩家的手臂挥动（默认开启）。*注：有动作的情况下可能会影响隔壁的游玩。*
*   **沉浸模式**：不使用GUI游戏，而是和VR一样将游戏画面显示在屏幕上。
*   **隐藏手臂**：游玩过程中在第一人称视角下隐藏手臂与手中物品。
*   **键盘大音符判定**：键盘端想要满分打大音符，**必须同时按下两边的鼓边或两边的鼓面**（模拟双手击打），单边按键只能获得非满分的普通判定。

### 6.3 仅限 VR 端设置
*   **鼓面打击显示**：默认打开。**备注说明**：“敲击鼓面的时候，鼓面会显示敲击的反应（对应的鼓面会变红鼓边会变蓝）以便玩家得知自己是否正确敲击。” *（底层逻辑：仅触发判定区亮起，并且鼓边的高亮范围必须严格限制在空心圆环区，绝不溢出到太鼓外部判定空间，确保视觉反馈与实际判定逻辑高度一致）。*
*   **大触滚奏模式**：*默认情况下，为防止误解，玩家将鼓棒伸入太鼓感应区后，在不离开太鼓的情况下移动到其他判定区，不会触发其他感应区的判定。开启后即可扫描触发其他感应区（对于幽灵之乱等歌曲会很有用）。*注：不建议新手或未接触太鼓的玩家开启此模式。
*   **力度判定**：检测玩家击打太鼓时的挥动速度，开启此模式后大音符无需双手，只需稍用力即可完成满分判定。

### 6.4 共通设置项
*   **隐藏隔壁玩家**：防止有些人故意捣乱阻拦视野，开启此项即可在游玩的时候隐藏对方的身体与模型。
*   **独享模式**：隐藏隔壁玩家的另一种版本，开启后隐藏除了你与对手之外所有玩家的身体与模型。
*   **高度校准**：可以调整玩家身高，以便以最佳手感游玩太鼓。*注：GUI模式下也可以设置，不过没什么用。*
*   **自动对齐**：进入游戏后会自动将玩家的视角调整到面向太鼓的位置，需要保持游戏开始前的时候面向前方。
*   **禁用移动**：进入游戏后禁用WASD或者摇杆将玩家移动位置，仅在潜行时才可调整位置。*注：GUI模式下此项目没有影响。*

### 6.5 外设桥接设置
*   **实体太鼓模式**：开启后可以连接玩家的自备实体太鼓，请确保玩家拥有实体太鼓再开启此项。开启之前需在设置中从引导内连接外设，开启成功后即可使用太鼓控制器外设游玩。此模式下可以检测玩家敲鼓力度，大音符无需双手，只需稍用力即可完成满分判定。VR开启此模式后将自动禁用游戏内的太鼓感应区，并自动进入高度调整界面确保能够将游戏内的太鼓与实体鼓对齐，并推荐开启“禁用移动”。

## 7. 游戏币与进入游戏引导 (Arcade & Onboarding)

### 7.1 游戏币设计与消耗
*   **游戏币物品**：新增“游戏币”物品，可通过合成获得（默认3个铁粒合成1个游戏币，或使用金粒合成更高级的游戏币）。
*   **投币机制**：玩家在使用鼓棒右键太鼓机台游玩前，需要先消耗游戏币（默认一次游玩消耗一定数量）。
*   **自定义消耗**：服务器管理员（OP）可以通过指令任意设置游玩所需的消耗物品和数量，以及设置不同游戏币是否可互相合成及配方。

### 7.2 进入游戏引导流程
玩家手持鼓棒对准机台右键（交互）即可进入机台模式。首次进入时，会让玩家选择游玩方式（PC 端操控 / VR 端操控），并开启引导：

*   **PC 端引导**：
    *   打开 GUI 并完成首次引导，包括键位设置（新手推荐 DJFK / 老手推荐 DFJK / 自定义键位）。
    *   随后进入游戏内界面，即可开始选歌，或者进行校准与设置项。
*   **VR 端引导**：
    *   打开悬空 GUI 开始引导，设置鼓棒在手里的倾斜角度（会影响打击手感）。
    *   随后弹出新手教程引导（如何游玩太鼓，可跳过）。
    *   跳过教程或点击关闭后，关闭 GUI，所有游戏画面全部显示在街机的屏幕上。玩家可以自行选歌，也可以用手触碰街机最下方的按钮打开 GUI 设置界面。

## 8. 曲包管理与管理员指令 (Content & OP Control)

### 8.1 曲包导入与可见性
*   **手动导入**：游戏不提供任何内置曲包，玩家必须手动导入本地曲包（支持 `.tja` 和 `.osz` 格式）。
*   **可见性限制**：刚导入的曲包，默认**仅自己可见**。或者，仅在玩家与隔壁玩家（比如双人同屏机台）游玩时互相可见。
*   **公开机制**：玩家导入曲包后，需要手动上传曲包到审核队列。OP 决定是否将曲包设置为**公开曲包**（所有玩家都可以选择），或者在服务器下载时弹出确认。

### 8.2 管理员 (OP) 指令系统
*   **审核指令**：`/taikomc adminlist`。OP 使用此指令可以审核玩家上传的曲包是否放行，以及管理曲包对应的归类，或者修改玩家上传到公开曲包时是否需要经过审核。
*   **音效设置指令**：`/taikomc screen setting`。用于切换旁观者/大屏幕的音效播放模式（正解音 / 实际敲击）。
*   **经济控制**：OP 可以设置游玩所需消耗的游戏币数量、支持哪些物品作为游戏币，以及设置合成配方。

## 9. 开发路线图 (Roadmap)
1.  **Phase 1**: 基础 TJA/OSZ 解析、PC 端下落式判定、键盘双键大音符判定、基础音频同步、延迟校准 GUI。
2.  **Phase 2**: VR 控制器接入、立体同心圆柱碰撞判定、红线左右半区判定、蓝线滚奏线段采样、VR专属设置项（含鼓面打击显示反馈）。
3.  **Phase 3**: 实体太鼓外设（手柄/MIDI）桥接、实体太鼓模式设置、游戏币系统与投币机台交互。
4.  **Phase 4**: 网络包设计、大屏幕渲染、观战延迟补偿、多人与旁观者音效规则、共通设置项、曲包审核系统与 OP 指令。
